RouteX 4.0.2 — Startup and monitor fixes


- **Fixed: the window could stay on "RouteX · Loading" forever.** The loading screen waited for WebView2 to paint frames; when the page was not being painted (window covered or hidden, GPU process stalled) it never went away. Every step of the startup now has a time limit, and a watchdog shows the interface anyway if it is still loading after 12 s.
- If Microsoft Edge WebView2 cannot start at all (30 s), RouteX now opens its classic built-in interface instead of hanging or closing. The reason is written to the log and to `config\runtime\interface-startup.txt`.
- The connection engine (auto-connect, DPI, monitoring) starts before the interface, so a slow interface no longer delays the VPN.
- **Fixed: false ping jumps on the Monitor chart.** Every second the chart animated each point towards its neighbour's value, so a flat line looked like it was jumping. The scale now follows the bulk of the samples (as in 3.x), so one slow probe no longer squashes the graph; spikes stay at the top edge.
- Fewer antivirus false positives: "Restart now" after an update no longer runs a hidden PowerShell with an encoded command, and the standalone RouteX.exe no longer loads the WebView2 libraries from memory. It writes them next to the exe once and loads them from disk.

Close RouteX before replacing the executable. Keep your config and core folders. Requires .NET Framework 4.8 and Microsoft Edge WebView2 Runtime.
